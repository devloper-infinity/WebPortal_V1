# Housekeeping module deployment

1. For a new installation, run `01_CreateTables.sql`, `02_CreateIndexes.sql`, `03_Procedures.sql`, then `07_InspectionActivityLookup.sql` against the WebPortal `MainCon` database.
2. For an existing installation, back up the database and run `04_BranchFloorMigration.sql`, `05_StaffSupervisorEmployeeMigration.sql`, `06_ScheduleSupervisorEmployeeMigration.sql`, and `08_InspectionSupervisorEmployeeMigration.sql`, followed by the updated indexes, procedures, and `07_InspectionActivityLookup.sql`. The Branch/Floor migration adds `BranchID` while retaining all old Building/Location data and tables. It does not infer how a Building maps to a Branch. Before enabling the new pages, populate BranchID for existing floors and dependent records using an approved business mapping, then reconcile their BranchID/FloorID pairs.
3. In the existing WebPortal menu editor (`Admin/ChildPages.aspx`), create a Housekeeping parent item, then add Dashboard, Master Management, Activity Management, and Report Management as its children. Use `../Admin/HousekeepingDashboard.aspx`, `../Admin/HK_MasterManagement.aspx`, `../Admin/HK_ActivityManagement.aspx`, and `../Admin/HK_ReportManagement.aspx` for their URLs. Assign these four entries independently through `Admin/AssignGroupMenus.aspx`. The consolidated pages, legacy Housekeeping URLs, and their AJAX methods check the signed-in user's existing group menu rights; adding a link alone does not grant access.
4. Branch choices use the existing `new bllMaster().GetAllBranches()` lookup. No separate Branch Master is created.
5. The application resolves the employee ID from `Session["EmployeeID"]`, then a numeric `Session["UserName"]`/authenticated name. Confirm the existing login identity is numeric or populate that session value before enabling the module.
6. Open the Dashboard or one of the three management pages from the WebPortal menu. Master, Activity, and Report features appear as internal tabs on their corresponding pages. The Dashboard remains independent. Building Master and Location Master pages have been removed from this module.

The scripts are rerunnable and do not delete table data. Floor entries are unique by BranchID and floor number/name. Housekeeping Staff, Activity Schedule, Activity Assignment, and Inspection `SupervisorID` values reference `EmployeeInfo.EmployeeID`, matching the employee supervisor identity. The revised save procedure validates supervisor and floor selections. Master deactivation is soft-delete. SQL scripts must be applied to the target database by an authorized database operator; they are not run by the application build.
